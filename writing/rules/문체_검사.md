# 국문 문체 — 검수

> 작성이 끝난 뒤에 읽는다. 규칙 본문은 `문체.md` 에 있다.

**생성과 검수는 분리한다.** 규칙을 생성 프롬프트에 한꺼번에 넣으면 준수율이 떨어진다.
검수는 별도 패스로 돌리고, 문장 전체를 다시 쓰게 하지 말고 **위반 구간만 고치게** 한다.
그래야 원문 정보 손실이 적다. 재검사는 최대 2회까지만 돈다.

## 1. 어휘·표현 패턴

```regex
# B2: 이중 피동 / 행위자를 숨기는 수동태
/되어지|지게\s?되었|어지게|에\s?의해|자동화되었|개선되었|해결되었/

# 3절(단정과 헤징): 헤징
/것\s?같습니다|생각됩니다|한\s?편입니다|나름|조금이나마|어느\s?정도|다소|기여한\s?부분/

# B7: 번역체
/을\s?가지고\s?있|를\s?보유하고\s?있|에\s?대하여|에\s?관하여|중의\s?하나|필요로\s?하/

# B8: 무색 동사
/진행하였|수행하였|담당하였|참여하였|진행했|수행했/

# B6: 모호 지시어
/해당\s|이러한\s|그것은|상기\s|동\s?프로젝트/

# 4절(수치): 정량화 누락 신호 — 수치로 바꾸거나 지운다
/대규모|다양한|많은|크게\s?개선|상당히|매우/
```

### B9 연어 패턴

목적어와 서술어의 짝을 보는 검사라 정규식이 목적어까지 함께 잡아야 한다.
**판정은 읽어서 한다** — 아래는 후보 탐지용이다.

```regex
# B9-1: 절차·동작 명사 + 열다/닫다 (영어 open/close 직역)
#       외래어 '오픈'은 걸리지 않는다 — 의도적이다
/(접수|신청|모집|예약|주문|등록|판매|공모)(을|를|가|이)\s?(열|닫)/

# B9-2: 관용구 밖의 '밟다' — 앞 명사를 함께 잡는다
#       절차·단계·수순이면 정상이므로 읽고 버린다
/[가-힣A-Za-z0-9]+(을|를|이|가)\s?밟/

# B9-3: 없는 피동형 — 피동형이 없는 동사에 -이/히/리/기를 붙인 꼴
/밟히|겪히|짚히|거쳐지|치뤄지/
```

`B9-2`에 부정형 선읽기(`(?!절차|단계|수순)`)를 붙이지 않는 이유는 `[가-힣]+`가
역추적하면서 `절차를 밟`을 `차를 밟`으로 다시 맞춰 선읽기를 우회하기 때문이다.
목적어까지 잡아 놓고 읽어서 거르는 편이 확실하다.

## 2. 문장 구조 패턴

정규식만으로는 오탐이 많다. **후보 탐지용으로만 쓰고 판정은 읽어서 한다.**

```regex
# B1: 사물 주어 + 능동 타동사 — 사물이 그 동사의 행위자인지 읽어서 가른다
#     행위자면 정상이다 (서버가 요청을 처리한다)
/(은|는)\s.{0,25}(분리해|나눠|쪼개|처리해|구성해|적용해|연결해|묶어),/

# B1: 한 절에 피동+능동 혼재
/(되지|지지|이지)\s?않(게|도록).{0,15}(해|하여),/

# B3: 쉼표 연결 2회 이상
/[가-힣]+(해|여|하며|으며),.*?[가-힣]+(해|여|하며|으며),/

# B3: 문장 길이 초과 (80자)
/[^.!?\n]{80,}[.!?]/

# B4: 목적어-서술어 거리 과다 (을/를 이후 10어절 이상)
#     문장 경계를 넘지 않도록 마침표를 제외한다. 문말 서술어까지의 거리만 재므로
#     실제로는 '긴 문장' 탐지에 가깝다 — 판정은 반드시 읽어서 한다.
/(을|를)\s([^.!?\s]+\s){10,}[^.!?\s]+(했습니다|합니다|입니다)/

# B5: 동작 명사 목적어 + 구조/시스템 결합
/[가-힣]+(을|를)\s(비동기|이벤트\s?기반|병렬|분산)?\s?(구조|시스템|파이프라인|아키텍처)(로|으로)\s?(설계|구축|구현)/

# B6: 지칭 후 다른 명사로 재지칭
/(하나|이것|그것)(가|이).{0,20}(해도|하면|이면).{0,20}그\s[가-힣]+(만|는|은|이|가)/
```

## 3. 문장 사이 패턴

**검사 단위가 문장 하나가 아니다.** 1·2절을 전부 통과한 문장도 여기서 걸리므로,
앞 문장과 붙여 읽어야 판정할 수 있다.

```regex
# C1: 부정 대조 — 부정되는 쪽이 앞 문장에 세워졌는지 읽어서 본다
/[가-힣A-Za-z0-9]+(이|가)\s?아니라|[가-힣A-Za-z0-9]+보다는|[가-힣A-Za-z0-9]+\s대신/

# C1: 역접 접속 — 앞 문장과 실제로 대립하는지 본다. 문장 첫머리만 잡는다
/(^|[.!?]\s)(하지만|그러나|반면)/

# C2: 인과 접속 — 앞 문장이 실제 원인인지 읽어서 가른다
/때문입니다|따라서|그러므로|[가-힣]므로\s/
```

세 패턴 모두 정상 용례가 훨씬 많다.
**적중 건수는 무의미하고, 걸린 자리를 앞 문장과 함께 읽는 것이 검사다.**

## 4. 형식 패턴

```regex
# 날짜 형식 위반 → 2024.03 으로 통일
/\d{1,2}\/\d{1,2}\/\d{4}|\d{4}-\d{2}-\d{2}/

# 천 단위 콤마 누락 → 검토 대상
/\d{5,}/
```

## B1 판정법

정규식에 걸린 문장을 절로 나눠 숨은 주어를 하나씩 적는다. 이 검사는 규칙 위반 여부보다
**판독 부하**를 보는 것이라 읽고 내리는 판정이 정규식보다 훨씬 정확하다.

```
다음 문장의 각 절을 나누고, 절마다 숨은 주어(생략된 주어 포함)를 표기하라.

문장: {sentence}

출력 형식:
- 절1: "..." → 숨은 주어: ...
- 절2: "..." → 숨은 주어: ...
판정: 서로 다른 주어가 2개 이하이면 PASS, 3개 이상이면 FAIL
FAIL인 경우 다음 두 방식 중 하나로 재작성하라.
  A) 주어를 행위자로 통일하고 사물은 목적어로 내린다
  B) 사물을 주어로 두되 모든 서술어를 상태·피동으로 통일한다
원문의 기술적 사실은 하나도 빠뜨리지 말 것.
```

다시 쓸 때는 **그 문단 끝까지 한 방식을 유지**한다.

## B9 판정법

B1 판정에서 주어가 2개 이하로 나왔는데도 어색하면 서술어를 본다.
사전 검색 없이 판정하므로 **모어 화자의 용례 기억을 끌어내는 형태**로 묻는다.

```
다음 문장에서 목적어(또는 주어)와 서술어의 짝을 하나씩 뽑아라.

문장: {sentence}

짝마다 아래 넷을 차례로 답하라.
1. 그 서술어가 흔히 받는 목적어를 3~4개 적는다. 문제의 명사가 같은 부류인가?
2. 그 서술어가 관용구의 일부인가? (절차를 밟다, 수순을 밟다 …)
   관용구면 구성 어휘를 바꿀 수 없고 피동형도 만들 수 없다.
3. 그 서술어의 반대말로 문장을 뒤집어라. 자연스러운 반대말이
   다른 어휘 계열이면(접수 마감 ↔ 접수 시작) 원래 서술어가 틀린 것이다.
4. 피동형인가? 그렇다면 -이/히/리/기가 실제로 쓰이는 동사인가?

판정: 넷 모두 통과하면 PASS, 하나라도 걸리면 FAIL
FAIL이면 -되다가 붙는 한자어 등 짝이 성립하는 서술어로 바꿔 다시 써라.
원문의 기술적 사실은 하나도 빠뜨리지 말 것.
```

## C 판정법

B1·B9를 통과했는데도 뜬금없이 읽히면 앞 문장을 함께 넣는다.
**앞 문장을 빼고 물으면 이 결함은 잡히지 않는다** — 문제 문장만 놓고 보면 아무 하자가 없다.

```
앞 문장과 문제 문장을 함께 읽고 답하라.

앞 문장: {prev_sentence}
문장: {sentence}

1. 문장의 접속 유형을 고른다 — 대조 / 역접 / 인과 / 없음.
   '없음'이면 PASS로 끝낸다.
2. 대조·역접이면 부정되거나 대립되는 쪽을 한 구절로 뽑아라.
   그 내용이 앞 문장에 있는가?
3. 인과면 문장에 "왜?"를 묻고 답을 한 줄로 적어라. 앞 문장이 그 답인가?

판정: 2 또는 3의 답이 앞 문장에 있으면 PASS, 없으면 FAIL
FAIL이면 다음 두 방식 중 하나로 재작성하라.
  A) 앞 문장에 전제를 세우고 접속을 유지한다
  B) 접속을 버리고 뒤 문장만 단언한 뒤 근거를 다음 문장에 붙인다
원문의 기술적 사실은 하나도 빠뜨리지 말 것.
```

문단의 첫 문장은 앞 문장이 문단 밖에 있다. **문단 경계를 넘어 앞 문장을 가져와서 검사한다** —
문서 전체의 리드 문단이라 앞 문장이 아예 없으면 제목을 앞 문장으로 놓는다.

## 전후 비교 — 기술 구조 서술

문법 오류는 없으나 한국어 화자가 어색함을 느끼는 전형이다.

**Before**
```
이미지 변환을 여러 워커 프로세스가 대기열에서 꺼내 처리하는 비동기 구조로
설계했습니다. 작업은 개별 단위로 나눠, 실패하면 그 단위만 재시도합니다.
엔진은 특정 업무에 묶이지 않게 분리해, 소스 획득 방식(압축파일·단일파일·원격)이
달라져도 같은 구조를 재사용합니다.
```

| 문제 | 규칙 |
|---|---|
| 1문장: `이미지 변환을`이 문미 `설계했습니다`까지 8어절 떨어짐 | B4 |
| 1문장: 동작 명사 `이미지 변환`이 `구조로 설계했다`의 목적어 자리 | B5 |
| 2문장: 숨은 주어 3개 (나 → 작업 → 시스템) | B1 |
| 3문장: 숨은 주어 4개 (나 → 엔진 → 소스 획득 방식 → 나) | B1 |
| 3문장: `묶이지 않게`(피동) + `분리해`(능동) 혼재 | B1 |
| 2·3문장 모두 `-해,` `-눠,` 동일 리듬 반복 | B3 |
| 괄호 삽입으로 문장 흐름 단절 | B3 |

**After — 방식 A (행위자 주어)**
```
여러 워커 프로세스가 대기열에서 작업을 꺼내 변환하는 비동기 구조를 설계했습니다.
작업을 개별 단위로 쪼개 등록해, 실패한 단위만 다시 처리하면 됩니다.
소스 획득을 변환 앞 단계로 떼어냈습니다. 압축파일·단일파일·원격 어느 쪽으로
들어와도 변환 엔진은 하나입니다.
```

**After — 방식 B (사물 주어 + 상태 서술)**
```
이미지 변환은 여러 워커 프로세스가 대기열에서 꺼내 처리하는 비동기 구조입니다.
작업은 개별 단위로 쪼개져 있어, 실패한 단위만 다시 처리됩니다.
소스 획득은 변환과 별도 단계로 나뉘어 있습니다. 압축파일·단일파일·원격
어느 쪽으로 들어와도 변환 엔진은 하나입니다.
```

> **3문장을 둘로 끊은 이유** — 이전 예시는 `변환 엔진은 … 분리했기 때문에`로 B1을 그대로
> 어겼다 — 엔진은 분리의 대상이지 주체가 아닌데 능동 타동사가 붙었다.
> `소스를 어디서 가져오든`은 `압축파일·단일파일`(형태)과
> `원격`(위치)을 한 열거에 묶어 층위가 어긋났다. 무엇보다 "엔진을 업무에서 분리했으므로
> 소스가 어디서 오든 같은 엔진"은 인과가 성립하지 않는다. 같은 엔진을 쓰는 근거는 소스
> 획득을 변환 앞 단계로 분리한 것이다. **After 예시는 규칙을 어기지 않는지 스스로 검사한
> 뒤 싣는다.**

## 전후 비교 — 연어 위반

B1 위반과 B9 위반이 한 문장에 겹친 전형이다.

**Before**
```
02·03은 코드값과 스텝 정의는 시딩되어 있으나 분기 구현 전에는 접수를 열면 안 된다 —
열면 01의 순서를 그대로 타고, 각 업무의 실제 스텝이 밟히지 않는다.
```

| 문제 | 규칙 |
|---|---|
| 숨은 주어 4개 (코드값·정의 → 우리 → ? → 스텝) | B1 |
| `시딩되어 있으나`(피동) + `열면 안 된다`(능동) 혼재 | B1 |
| `은 … 는` 이중 주제격으로 문장의 주제가 흐려짐 | B1 |
| 93자, `-으나` + `—` + `-고,` 로 연결 장치 3중 | B3 |
| `접수를 열다` — `열다`의 목적어 부류에 절차가 없음 | B9-1 |
| `스텝을 밟다` — 관용구 `절차를 밟다`의 어휘를 외래어로 교체 | B9-2 |
| `밟히다` — 물리적으로 눌리는 뜻만 있는 피동형 | B9-3 |

**After — 방식 A (행위자 주어)**
```
02·03은 코드값과 스텝 정의까지만 시딩해 뒀다.
분기를 구현하기 전에는 이 두 업무의 접수를 받지 않는다.
받으면 접수 건이 01의 순서를 그대로 타서 각 업무의 실제 스텝을 건너뛴다.
```

> **자체 검사** — 세 문장 모두 숨은 주어 2개 이하, 최장 43자, 쉼표 연결 0회, 능동 통일.
> `접수를 받다`·`스텝을 건너뛰다`는 연어가 성립한다. 개발자 은어인 `순서를 타다`는
> `로직을 타다`·`분기를 타다`로 굳어 있어 B9에 걸리지 않는다 — **업계에서 굳은 용법이면
> 표준 연어가 아니어도 통과시킨다.** `접수 건이 … 타서`는 사물 주어에 능동 타동사가 붙었지만
> 접수 건이 실제로 순서를 타는 행위자라 B1에도 걸리지 않는다.
