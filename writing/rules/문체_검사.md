# 국문 문체 — 검수

> 작성이 끝난 뒤에 읽는다. 규칙 본문은 `문체.md` 에 있다.

**생성과 검수는 분리한다.** 규칙을 생성 프롬프트에 한꺼번에 넣으면 준수율이 떨어진다.
검수는 별도 패스로 돌리고, 문장 전체를 다시 쓰게 하지 말고 **위반 구간만 고치게** 한다.
그래야 원문 정보 손실이 적다. 재검사는 최대 2회까지만 돈다.

## 1. 어휘·표현 패턴

```regex
# B2: 이중 피동 / 행위자를 숨기는 수동태
/되어지|지게\s?되었|어지게|에\s?의해|자동화되었|개선되었|해결되었/

# 2절: 헤징
/것\s?같습니다|생각됩니다|한\s?편입니다|나름|조금이나마|어느\s?정도|다소|기여한\s?부분/

# B7: 번역체
/을\s?가지고\s?있|를\s?보유하고\s?있|에\s?대하여|에\s?관하여|중의\s?하나|필요로\s?하/

# B8: 무색 동사
/진행하였|수행하였|담당하였|참여하였|진행했|수행했/

# B6: 모호 지시어
/해당\s|이러한\s|그것은|상기\s|동\s?프로젝트/

# 3절: 정량화 누락 신호 — 수치로 바꾸거나 지운다
/대규모|다양한|많은|크게\s?개선|상당히|매우/
```

## 2. 문장 구조 패턴

정규식만으로는 오탐이 많다. **후보 탐지용으로만 쓰고 판정은 읽어서 한다.**

```regex
# B1: 사물 주어 + 능동 타동사
/(은|는)\s.{0,25}(분리해|나눠|쪼개|처리해|구성해|적용해|연결해|묶어),/

# B1: 한 절에 피동+능동 혼재
/(되지|지지|이지)\s?않(게|도록).{0,15}(해|하여),/

# B3: 쉼표 연결 2회 이상
/[가-힣]+(해|여|하며|으며),.*?[가-힣]+(해|여|하며|으며),/

# B3: 문장 길이 초과 (80자)
/[^.!?\n]{80,}[.!?]/

# B4: 목적어-서술어 거리 과다 (을/를 이후 10어절 이상)
#     문장 경계를 넘지 않도록 마침표를 제외한다. 문말 서술어까지의 거리만 재므로
#     실제로는 '긴 문장' 탐지에 가깝다 — 판정은 반드시 읽어서 한다.
/(을|를)\s([^.!?\s]+\s){10,}[^.!?\s]+(했습니다|합니다|입니다)/

# B5: 동작 명사 목적어 + 구조/시스템 결합
/[가-힣]+(을|를)\s(비동기|이벤트\s?기반|병렬|분산)?\s?(구조|시스템|파이프라인|아키텍처)(로|으로)\s?(설계|구축|구현)/

# B6: 지칭 후 다른 명사로 재지칭
/(하나|이것|그것)(가|이).{0,20}(해도|하면|이면).{0,20}그\s[가-힣]+(만|는|은|이|가)/
```

## 3. 형식 패턴

```regex
# 날짜 형식 위반 → 2024.03 으로 통일
/\d{1,2}\/\d{1,2}\/\d{4}|\d{4}-\d{2}-\d{2}/

# 천 단위 콤마 누락 → 검토 대상
/\d{5,}/
```

## B1 판정법

정규식에 걸린 문장을 절로 나눠 숨은 주어를 하나씩 적는다. 이 검사는 규칙 위반 여부보다
**판독 부하**를 보는 것이라 읽고 내리는 판정이 정규식보다 훨씬 정확하다.

```
다음 문장의 각 절을 나누고, 절마다 숨은 주어(생략된 주어 포함)를 표기하라.

문장: {sentence}

출력 형식:
- 절1: "..." → 숨은 주어: ...
- 절2: "..." → 숨은 주어: ...
판정: 서로 다른 주어가 2개 이하이면 PASS, 3개 이상이면 FAIL
FAIL인 경우 다음 두 방식 중 하나로 재작성하라.
  A) 주어를 행위자로 통일하고 사물은 목적어로 내린다
  B) 사물을 주어로 두되 모든 서술어를 상태·피동으로 통일한다
원문의 기술적 사실은 하나도 빠뜨리지 말 것.
```

다시 쓸 때는 **그 문단 끝까지 한 방식을 유지**한다.

## 전후 비교 — 기술 구조 서술

문법 오류는 없으나 한국어 화자가 어색함을 느끼는 전형이다.

**Before**
```
이미지 변환을 여러 워커 프로세스가 대기열에서 꺼내 처리하는 비동기 구조로
설계했습니다. 작업은 개별 단위로 나눠, 실패하면 그 단위만 재시도합니다.
엔진은 특정 업무에 묶이지 않게 분리해, 소스 획득 방식(압축파일·단일파일·원격)이
달라져도 같은 구조를 재사용합니다.
```

| 문제 | 규칙 |
|---|---|
| 1문장: `이미지 변환을`이 문미 `설계했습니다`까지 8어절 떨어짐 | B4 |
| 1문장: 동작 명사 `이미지 변환`이 `구조로 설계했다`의 목적어 자리 | B5 |
| 2문장: 숨은 주어 3개 (나 → 작업 → 시스템) | B1 |
| 3문장: 숨은 주어 4개 (나 → 엔진 → 소스 획득 방식 → 나) | B1 |
| 3문장: `묶이지 않게`(피동) + `분리해`(능동) 혼재 | B1 |
| 2·3문장 모두 `-해,` `-눠,` 동일 리듬 반복 | B3 |
| 괄호 삽입으로 문장 흐름 단절 | B3 |

**After — 방식 A (행위자 주어)**
```
여러 워커 프로세스가 대기열에서 작업을 꺼내 변환하는 비동기 구조를 설계했습니다.
작업을 개별 단위로 쪼개 등록해, 실패한 단위만 다시 처리하면 됩니다.
소스 획득을 변환 앞 단계로 떼어냈습니다. 압축파일·단일파일·원격 어느 쪽으로
들어와도 변환 엔진은 하나입니다.
```

**After — 방식 B (사물 주어 + 상태 서술)**
```
이미지 변환은 여러 워커 프로세스가 대기열에서 꺼내 처리하는 비동기 구조입니다.
작업은 개별 단위로 쪼개져 있어, 실패한 단위만 다시 처리됩니다.
소스 획득은 변환과 별도 단계로 나뉘어 있습니다. 압축파일·단일파일·원격
어느 쪽으로 들어와도 변환 엔진은 하나입니다.
```

> **3문장을 둘로 끊은 이유** — 이전 예시는 `변환 엔진은 … 분리했기 때문에`로 B1을 그대로
> 어겼다(사물 주어 + 능동 타동사). `소스를 어디서 가져오든`은 `압축파일·단일파일`(형태)과
> `원격`(위치)을 한 열거에 묶어 층위가 어긋났다. 무엇보다 "엔진을 업무에서 분리했으므로
> 소스가 어디서 오든 같은 엔진"은 인과가 성립하지 않는다. 같은 엔진을 쓰는 근거는 소스
> 획득을 변환 앞 단계로 분리한 것이다. **After 예시는 규칙을 어기지 않는지 스스로 검사한
> 뒤 싣는다.**
