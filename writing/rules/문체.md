# 국문 문체 — 기본 규칙

> 에이전트가 한국어를 쓸 때 적용한다. 문서 종류를 가리지 않는다 —
> 기술 문서, README, 커밋 메시지, 이슈·PR 본문, 사용자에게 보내는 설명 모두 해당한다.
> 검수용 정규식은 `문체_검사.md` 에 있다(작성 중에는 읽지 않는다).

특정 문서 양식(이력서·기획서 등)의 규칙은 여기 두지 않는다. 그 문서를 쓰는 프로젝트의 `rules/` 에 둔다.

## 1. 문장 구조

### B1. 한 문장 안에서 숨은 주어를 바꾸지 않는다 ★

한국어는 주어를 생략하므로, 절마다 숨은 주어가 달라지면 읽는 사람이 매번 주어를 다시 추론해야 한다.
**LLM이 쓴 한국어가 어색한 가장 큰 원인이다. 한 문장에 서로 다른 주어가 3개 이상이면 다시 쓴다.**

❌ 작업은 개별 단위로 나눠, 실패하면 그 단위만 재시도합니다.

| 절 | 숨은 주어 |
|---|---|
| 작업은 개별 단위로 **나눠** | 나(글쓴이) |
| **실패하면** | 작업 / 단위 |
| 그 단위만 **재시도합니다** | 시스템 또는 나 |

`작업은`을 주제로 던진 직후 능동 타동사 `나눠`가 붙어, 순간 "작업이 무언가를 나눈다"로 읽힌다.
문법 오류는 아니지만 판독 부하가 크다.

❌ 엔진은 특정 업무에 묶이지 않게 분리해, 소스 획득 방식이 달라져도 같은 구조를 재사용합니다.
   → 나 → 엔진 → 소스 획득 방식 → 나, 4개. `묶이지 않게`(피동)와 `분리해`(능동)도 한 절에 섞였다.

고치는 방법은 두 가지이고, **문단 단위로 하나만 골라 끝까지 쓴다.** 한 문단에서 섞으면 같은 문제가 반복된다.

| 방식 | 형태 | 예시 |
|---|---|---|
| A. 행위자를 주어로 | `A를 ~했다` | 변환 엔진을 업무 로직과 분리했습니다 |
| B. 사물을 주어로 + 상태 서술 | `A는 ~되어 있다` | 변환 엔진은 업무 로직과 분리되어 있습니다 |

**사물 주어에 능동 타동사를 붙이는 것**(`엔진은 … 분리해`)이 위반이다.

### B2. 행동은 능동으로, 구조는 상태로 쓴다

수동태가 항상 틀린 것은 아니다. 누가 한 일을 수동태로 쓰면 행위자가 사라지므로 금지하고,
시스템 구조를 설명하는 상태 서술은 허용한다.

| 서술 대상 | 형태 |
|---|---|
| 사람이 한 행동 | 반드시 능동 — `배포 파이프라인을 구축했습니다` |
| 시스템의 구조·상태 | 상태 서술 허용 — `배포는 머지 시점에 자동 실행됩니다` |
| 지표의 변화 | 상태 서술이 자연스럽다 — `응답시간이 320ms로 줄었습니다` |

❌ 배포 프로세스가 자동화되었습니다 — 누가 했는지 사라진다.
❌ 응답 속도가 개선되었습니다 → ✅ 쿼리 인덱스를 재설계해 응답 속도를 40% 단축했습니다.
❌ 코드 리뷰 문화가 팀에 도입되었습니다 → ✅ 주 2회 코드 리뷰 세션을 제안해 팀에 정착시켰습니다.

금지 표현: `~에 의해`, `~되어지다`, `~지게 되었다`

### B3. 쉼표 연결은 한 문장에 1회까지

영어 분사구문을 직역한 리듬이다. `-해,` `-며,` 로 계속 이어붙이면 문장이 늘어지고 B1 위반이 따라온다.

❌ 엔진을 분리해, 방식이 달라져도 재사용하며, 실패 시 재시도합니다.
✅ 엔진을 업무 로직과 분리했습니다. 소스 획득 방식이 달라져도 엔진은 하나입니다.

인과 관계는 `-해,` 대신 `~했기 때문에`, `그 결과` 로 명시한다. 한 문장 60자 내외로 끊는다.

### B4. 목적어와 서술어를 떼어놓지 않는다

목적어와 그것을 받는 서술어 사이에 여러 어절이 끼면 독자가 문장을 중간에 다시 읽는다(garden path).

❌ 이미지 변환을 여러 워커 프로세스가 대기열에서 꺼내 처리하는 비동기 구조로 설계했습니다.
   → `이미지 변환을`이 `설계했습니다`의 목적어로 읽히다가, 끝에 가서야 `처리하는`의 목적어였음이 드러난다.

문장을 나누기 전에, 원인이 B5 형태인지 먼저 본다. 맞으면 B5로 고치는 편이 낫다.
그냥 나누면 B5 문제가 새로 생긴다.

△ 이미지 변환을 비동기 구조로 설계했습니다. 여러 워커 프로세스가 대기열에서 작업을 꺼내 처리합니다.
   → garden path는 피했지만 `이미지 변환`(동작 명사)이 `구조로 설계했다`의 목적어 자리에 앉았고(B5),
     두 문장을 이어줄 장치가 없어 뒷문장이 앞문장의 무엇을 구체화하는지 독자가 추론해야 한다.

### B5. 동작 명사를 구조·시스템과 바로 묶지 않는다

`OO을 구조/시스템/파이프라인으로 설계했다` 꼴에서 OO이 동작을 명사로 바꾼 말(변환·처리·전송·검증·저장)이면
목적어와 서술어의 범주가 어긋난다. **실제 설계 대상을 목적어로 세우고, 동작은 `~하는` 관형절로 내린다.**

❌ 이미지 변환을 비동기 구조로 설계했습니다.
✅ 여러 워커가 대기열에서 작업을 꺼내 변환하는 비동기 구조를 설계했습니다.

| 원래 문제 | 해소 방식 |
|---|---|
| 목적어(동작 명사)-서술어(설계하다) 범주 불일치 | 목적어를 구조·시스템 등 실체 명사로 교체 |
| 문장 간 연결 장치 없음 | 한 문장으로 응축, 관형절이 곧 구체화 |
| B4 위반 위험 | 관형절이 피수식 명사 바로 앞에 오므로 거리 0 |

한국어는 관형절이 피수식 명사 바로 앞에 오는 어순이 고정이라, B4와 B5를 동시에 푸는 것이 이 기법의 핵심이다.

**점검**: `OO을/를 (구조|시스템|파이프라인|아키텍처)로 (설계|구축|구현)` 이 보이면 OO이 동작 명사인지 확인한다.

### B6. 앞에서 가리킨 대상을 다른 명사로 다시 가리키지 않는다

❌ 하나가 실패해도 그 단위만 다시 처리합니다.  (앞: 하나 / 뒤: 단위 — 같은 대상을 다른 말로 지칭)
△ 한 단위가 실패해도 그 단위만 다시 처리합니다.  (명사는 맞췄지만 반복이 남는다)
✅ 실패한 단위만 다시 처리합니다.

지시어를 없애고 관형절로 합치는 것이 가장 낫다. 지시관형사(`그`, `이`) 자체가 위반은 아니다.

대명사·동의어로 갈아타는 것도 같은 문제다. 명사 반복이 오히려 명확하다.

❌ 결제 시스템을 개편했습니다. 그것은 안정성을 높였습니다.
✅ 결제 시스템을 개편해 결제 실패율을 2.1% → 0.3%로 낮췄습니다.

`해당`, `이러한`, `그것`, `상기`, `동 프로젝트`는 지시 대상을 흐리므로 고유명사를 반복한다.

### B7. 번역체

| ❌ | ✅ |
|---|---|
| ~을 가지고 있습니다 / 보유하고 있습니다 | ~이 있습니다 (또는 생략) |
| ~에 대하여 / ~에 관하여 | ~을 / ~의 |
| ~하는 것을 가능하게 했습니다 | ~할 수 있게 했습니다 |
| ~중의 하나입니다 | 대부분 삭제 가능 |
| 필요로 합니다 | 필요합니다 |

### B8. 무색 동사를 쓰지 않는다

`진행·수행·담당·참여`는 무엇을 했는지 드러내지 않는다. 구체 동사로 바꾼다.

| 무색 동사 | 대체 |
|---|---|
| 진행 / 수행 | 설계, 구현, 배포, 마이그레이션, 리팩터링, 튜닝 |
| 담당 | 주도, 설계, 운영, 개선, 자동화 |
| 참여 | (역할 명시) 구현, 리뷰, 아키텍처 설계 |

## 2. 단정과 헤징

**검증 가능한 사실은 단정한다.** 일상 한국어의 완곡어법은 문서에서 주장을 약화시킨다.

| ❌ | ✅ |
|---|---|
| ~에 기여한 부분이 있습니다 | ~을 주도해 ~을 달성했습니다 |
| 어느 정도 개선된 것 같습니다 | 30% 개선했습니다 |
| 도움이 되었다고 생각합니다 | (삭제하고 결과 수치로 대체) |

금지 표현: `것 같습니다`, `생각됩니다`, `~한 편입니다`, `나름`, `조금이나마`, `어느 정도`

**단, 실제로 불확실한 것을 단정하지는 않는다.** 검증하지 않은 값은 근거 범위를 함께 적는다 —
`약 30% 개선(사내 부하 테스트 기준)`. 이 절이 막는 것은 아는 사실을 흐리는 습관이지, 정직한 유보가 아니다.

## 3. 수치

정성 표현은 결과 지표로 바꾼다. 지표가 없으면 기간·인원·범위로 대체한다.

| ❌ | ✅ |
|---|---|
| 대규모 트래픽 처리 | 일 평균 200만 요청 처리 |
| 성능을 크게 개선 | p95 응답시간 1.2s → 320ms |
| 여러 서비스 개발 | 사내 3개 서비스의 인증 모듈 통합 |

`대규모`·`다양한`·`많은`·`크게`·`상당히`·`매우` 가 보이면 수치로 바꾸거나 지운다.

## 4. 표기

- 기술 스택·제품명은 공식 표기 그대로 — `PostgreSQL`, `Kubernetes`, `Node.js`.
- 천 단위 콤마를 넣고, 비율은 `%`를 붙여 쓴다(`40%`).
- 영문 약어는 첫 등장에 풀어 쓰고 이후 약어만 쓴다 — `CI/CD(지속적 통합·배포)`.
- 날짜는 `2024.03` 형식으로 통일한다.

## 검사법

문장이 어색한데 원인을 못 찾겠으면 절을 나눠 숨은 주어를 하나씩 적어 본다(B1).
서로 다른 주어가 3개 이상이면 그것이 원인이다.
