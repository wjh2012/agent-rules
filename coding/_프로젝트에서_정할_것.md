# 프로젝트에서 정할 것

여기 있는 항목들은 **agent-rules 가 답을 고르지 않는다.** 실제로 같은 팀의 두 프로젝트가
서로 다르게 답한 것들이라, 한쪽 답을 규칙으로 올리면 다른 쪽에서 틀린 규칙이 된다.

프로젝트를 시작할 때 아래를 정해 그 프로젝트의 `CLAUDE.md` 나 `docs/rules/` 에 적는다.
**판단 근거를 함께 적는다** — 근거가 없으면 다음 사람이 반대로 되돌린다.

---

## 응답

| 항목 | 선택지 | 고려할 것 |
|---|---|---|
| 성공 응답 | 공통 봉투(`BaseResponse<T>`) / 원시 DTO | 봉투는 클라이언트 분기점을 하나로 만들지만 매 응답에 한 겹이 붙는다 |
| 에러 응답 | 공통 봉투 / RFC 7807 `ProblemDetail` | 표준 포맷은 도구 지원을 받는다. 봉투는 성공·실패 형태가 같아진다 |
| CUD 응답 내용 | 처리된 리소스 ID / 빈 응답 | 빈 응답은 클라이언트가 결과를 다시 조회하게 만든다 |
| 추적 ID | 응답에 포함 / 로그에만 | 응답에 넣으면 외부에 내부 식별자가 노출된다. 넣을 거면 **요청마다 난수를 새로 만들지 말고** 로깅 컨텍스트의 실제 값을 쓴다 — 난수를 새로 만들면 로그와 대조가 안 되어 있으나 마나다 |

## HTTP

| 항목 | 선택지 | 고려할 것 |
|---|---|---|
| 허용 메서드 | 전부 / GET·POST 만 | 조직 보안 정책으로 제한되는 경우가 있다. **제한이 있으면 CUD 경로 패턴도 함께 정한다**(`POST /{id}/update` 등) |
| 조회 경로 | RESTful GET / 동사 서브경로 | 위 선택에 따라간다 |
| 벌크 작업 | 단건 경로 반복 / 별도 엔드포인트 + ID 목록 DTO | 단건 반복은 트랜잭션 경계가 흩어진다 |

## 예외

| 항목 | 선택지 | 고려할 것 |
|---|---|---|
| 도메인 예외 | 코드 enum 만 / 타입별 서브클래스 | 기본은 enum 만이다. 근거는 [spring-java/exception-handling.md](spring-java/exception-handling.md) |
| 오류 코드 | HTTP 상태를 직접 보유 / 래퍼 타입 경유 | 래퍼는 한 겹을 더한다. 직접 보유하면 그 모듈이 웹 의존을 갖는다 |

## 영속성

| 항목 | 선택지 | 고려할 것 |
|---|---|---|
| ORM | JPA / MyBatis | 규칙 상당수가 여기서 갈린다. MyBatis 는 [spring-java/mybatis/](spring-java/mybatis/) |
| PK 전략 | surrogate 일괄 / 테이블 설계를 따름(자연키·복합키 허용) | 레거시 스키마를 받으면 후자 외에 선택지가 없다 |
| 엔티티 필드명 | 전체 단어 / DB 컬럼 약어와 1:1 | 약어 스키마를 받으면 1:1 이 매핑 실수를 줄인다. 대신 코드 가독성을 잃는다 |
| 감사 일시 타입 | 날짜·시각 타입 / 문자열 | 레거시 스키마가 문자열이면 따라간다 |

## 언어·자료형

| 항목 | 선택지 | 고려할 것 |
|---|---|---|
| `record` 사용 | DTO 에 사용 / 전면 금지 | 하위 Java 호환이 필요하면 금지 외에 방법이 없다 |
| 모듈 분리 | 단일 모듈 / 실행 모듈 + 공유 모듈 | 워커·배치가 따로 뜨면 공유 모듈이 필요해진다 |

## 도구·정책

| 항목 | 고려할 것 |
|---|---|
| 코드 인스펙션 도구 | 사내 도구를 쓰면 **도구 오탐을 피하기 위한 규칙**이 생긴다. 그 규칙은 도구와 함께 사라지므로 범용 규칙과 섞지 않는다 |
| 스킬 매핑 | 어떤 요청에 어떤 스킬을 쓰는지 적는다. 안 적으면 스킬이 호출되지 않는다 |
| 클래스명 바인딩 | 공통 베이스 예외·전역 핸들러·응답 래퍼·파일 진입점의 실제 이름 |
