# 코드 스타일 — Java

> 여기 규칙 상당수는 C 계열 언어 공통이다. 예시만 Java 다.
> 규칙 자체보다 **왜 그런지**가 중요하다 — 근거를 모르면 도구가 지적할 때 오탐과 진짜를 구분하지 못한다.

## 1. 제어문의 중괄호를 생략하지 않는다

한 줄짜리 본문이어도 `{}` 를 붙인다. `else`·`else if` 도 같다.

```java
if (type == null) throw new IllegalArgumentException("...");   // ❌
if (type == null) {                                            // ✅
    throw new IllegalArgumentException("...");
}
```

줄바꿈해서 중괄호 없이 다음 줄에 본문을 두는 형태가 가장 위험하다. 나중에 한 줄을 덧붙이면
그 줄은 조건 밖에서 무조건 실행되는데 **들여쓰기는 조건 안처럼 보인다.**

삼항 연산자는 대상이 아니다. 다만 분기 안에서 부수효과가 일어나면 삼항이 아니라 `if` 블록으로 쓴다.

## 2. 루프 안에서 상수를 할당하지 않는다

반복해도 값이 달라지지 않는 대입은 루프 밖으로 끌어낸다. 매 반복 같은 값을 다시 만드는 코드는
**"이 값이 반복마다 달라진다"는 잘못된 신호**를 준다.

| 형태 | 예 |
|---|---|
| 리터럴 대입 | `String prefix = "IMG-";` |
| 상수 참조를 지역 변수로 받기 | `int max = Codes.MAX_RETRY;` |
| 루프 불변 표현식 | `Pattern.compile(...)` · `DateTimeFormatter.ofPattern(...)` · `new ObjectMapper()` |

마지막 부류는 재생성 비용도 실제로 크다. 클래스 전체에서 쓰면 `private static final` 필드로,
그 메서드 안에서만 쓰면 루프 직전에 선언한다.

반복마다 **새 인스턴스가 필요한** 대입(누적용 `StringBuilder`, 결과 담을 `List`)은 대상이 아니다.

### 2-1. 루프 지역 카운터 초기화는 예외다 — 끌어내면 버그다

반복마다 0부터 다시 세야 하는 카운터의 초기화는 리터럴 대입처럼 보이지만 상수 할당이 아니다.

```java
for (String root : roots) {
    int deleted = 0;                       // ✅ 루프마다 리셋돼야 하는 값
    for (Path file : expired) { ... }
    log.info("정리: root={}, {}건 삭제", root, deleted);
    totalDeleted += deleted;
}
```

**끌어내면 조용히 틀린다.** `int deleted` 를 루프 밖으로 옮기면 값이 루트 사이에 누적돼,
루트별 로그가 "이 루트에서 삭제한 건수"가 아니라 "여기까지 누계"로 바뀐다.
숫자가 여전히 그럴듯해서 아무도 눈치채지 못한다.

판별 기준은 한 문장이다 — **"두 번째 반복에서 이 변수가 첫 번째 반복의 값을 그대로 가져야 하는가?"**
그래야 하면 밖으로, 아니면 안이 맞다.

## 3. 한 줄에 문장 하나

디버거 중단점이 줄 단위라 한 줄에 두 문장이 있으면 **어디서 멈췄는지 구분되지 않는다.**
diff 도 무관한 변경을 한 줄로 묶어버린다.

```java
int a = 10; int b = 20;                          // ❌
private String failedStep, failErrCd;            // ❌ 콤마 다중 선언도 대상이다
```

`for (int i = 0; i < n; i++)` 의 세미콜론, 파라미터 목록, 문자열 안의 `;` 는 대상이 아니다.

## 4. `else` 를 동반하는 분기에서 조건을 부정형으로 쓰지 않는다

읽는 사람이 부정의 부정을 뒤집어야 하고, 그 과정에서 두 갈래를 반대로 읽는 사고가 난다.

```java
if (!found) { doB(); } else { doA(); }    // ❌
if (found) { doA(); } else { doB(); }     // ✅

String name = obj != null ? obj.getName() : fallback;   // ❌ 부정 조건이 앞
String name = obj == null ? fallback : obj.getName();   // ✅
```

- **`else` 가 없으면 대상이 아니다.** 조기 반환 가드는 부정형이어도 그대로 둔다 — 갈래가 하나뿐이다.
- **삼항을 중첩하지 않는다.** 갈래가 셋 이상이면 `if/else` 블록이나 별도 메서드로 뺀다.
- null 폴백은 삼항보다 `Objects.requireNonNullElse(a, b)` 가 낫다. 조건 자체가 사라진다.

## 5. 표현식 안에서 대입하지 않는다

한 표현식이 "값을 읽는다"와 "상태를 바꾼다"를 동시에 하면 부수효과가 눈에 띄지 않고,
`==` 오타와 시각적으로 구분되지 않는다.

```java
while ((entry = zis.getNextEntry()) != null) { ... }   // ❌

ZipEntry entry = zis.getNextEntry();                   // ✅ 대입과 판정을 분리
while (entry != null) {
    ...
    entry = zis.getNextEntry();
}
```

증감 연산자를 표현식 안에서 쓰는 것도 같다(`arr[i++]`·`foo(n++)`).
문장 단독의 `i++` 는 대상이 아니다. 연쇄 대입 `a = b = 0;` 도 금지다.

## 6. 같은 패키지·`java.lang` 을 import 하지 않는다

효과가 없으면서 **"이 타입은 다른 곳에 있다"는 잘못된 신호**를 준다.
하위 패키지는 다른 패키지다 — Java 패키지는 계층이 아니라 평면 이름이다.

클래스를 다른 패키지로 옮긴 뒤 원래 자리의 import 가 남는 것이 주된 발생 경로다.

## 7. `switch` — 화살표 형식을 쓰고 폴스루를 만들지 않는다

화살표(`->`) 형식은 **구조적으로 폴스루가 없어** `break` 자체가 필요 없다.
"`break` 누락"이라는 결함 유형이 사라진다.

콜론 형식을 유지하는 자리에서는 모든 case 가 `break`·`return`·`throw` 중 하나로 종단한다.
`return`·`throw` 로 끝나는 case 와 본문 없는 라벨 그룹핑은 폴스루 결함이 아니다.

### 7-1. `default` — 열린 입력에는 필수, enum 을 다 나열한 switch 에는 금지

| 대상 | `default` |
|---|---|
| `String`·`int` 등 열린 입력 | **필수** — 미상값을 조용히 무시하지 말고 `throw` 로 종단 |
| enum 전 상수를 나열한 switch 식 | **넣지 않는다** |

**enum switch 에 `default` 를 넣으면 컴파일러의 exhaustiveness 검사가 죽는다.**
상수를 나열한 switch 식은 새 enum 상수가 추가될 때 컴파일 에러로 누락을 알려주는데,
`default` 를 달면 새 상수가 조용히 `default` 로 흘러 분기 누락이 런타임까지 살아남는다.

여기에 `default` 를 추가하는 것은 수정이 아니라 **안전망 제거**다.

## 8. 문자열 연결

- 예외·오류 메시지, 수동 `toString()` → `String.format`
- 구분자로 잇기 → `String.join`
- 루프 내 반복 누적 → `StringBuilder` (여기가 유일한 자리)
- 로그 → 파라미터화 로깅 `log.info("id={}", id, e)`

**예외 메시지를 `StringBuilder` 로 바꾸지 않는다.** 최신 JDK 의 `+` 는 이미 `StringBuilder` 만큼
빠르다 — 이 규칙의 근거는 성능이 아니라 **가독성**이다. `String.format` 이 정답이다.

개수와 무관하게 항상 금지인 것 — 루프 내 `s += x` 누적(O(n²)),
**로그 인자 안의 `+`**(템플릿을 `{}` 로 써도 인자에서 조립하면 로그 레벨이 꺼져도 문자열을 만든다),
SQL 문자열 조립(인젝션).

## 9. 유틸리티 클래스

```java
public final class FileNames {          // final — 상속할 것이 없다는 의도를 드러낸다
    private FileNames() {}              // 인스턴스화 방지
    public static String sanitize(String name) { ... }
}
```

- 명시적 생성자가 전부 `private` 인 클래스는 `final` 을 붙인다. 정적 팩토리로만 생성한다는
  선언이므로 확장도 같이 막아 의도를 완결한다.
- 프레임워크가 호출하는 no-arg 생성자는 생성 경로가 아니므로 이 판정에서 제외한다.
- 상수만 있고 정적 메서드가 없는 클래스는 정상적인 상수 홀더다. 위반이 아니다.
- `enum` 은 생성자가 언제나 암묵적 `private` 이고 `final` 을 붙이면 컴파일 오류다. 대상이 아니다.

## 10. `abstract`

- **빈 메서드는 `abstract` 로 선언한다.** 빈 본문을 남기면 서브클래스가 구현을 빠뜨려도
  조용히 no-op 가 된다.
  - 예외는 템플릿 메서드의 선택적 훅이다. 이때는 훅임을 Javadoc 에 명시한다.
  - 빈 `record` 본문은 메서드가 아니라 타입 선언이다. 대상이 아니다.
- **`abstract` 메서드가 하나도 없는 `abstract` 클래스를 만들지 않는다.** 서브클래스가 반드시
  채워야 할 구멍이 없으면 `abstract` 는 잘못된 도구다 — 확장점이 있는 척하지만 아무것도
  강제하지 않아 읽는 사람이 무엇을 구현해야 하는지 알 수 없다.
  - 확장점이 없고 재사용 로직만 모아뒀다면 정적 유틸리티나 합성으로 바꾼다.
  - **예외는 상속 전용 상태 홀더**다. 필드를 서브클래스에 물려주려고 존재하며 자기 자신은
    인스턴스화되면 안 되는 클래스. 이때는 **Javadoc 첫 문장에 "상속 전용 — 직접 인스턴스화하지
    않는다"** 를 명시한다. 명시가 없으면 예외가 아니라 위반이다.

## 11. 빈 메서드·빈 생성자에 주석을 단다

본문이 빈 메서드·생성자는 **의도인지 미완성인지 코드만 봐서는 구분되지 않는다.**
주석 내용은 "비어 있는 이유"다. 시그니처를 재진술하는 주석은 없는 것과 같다.

반대로 **모든 생성자에 주석을 달지는 않는다.** DI 생성자에 "의존성을 주입한다"고 적는 것은
정보량이 0 이다. 검증 로직이 있거나 인자의 제약이 시그니처로 드러나지 않는 생성자에만 단다.

## 12. `volatile` 대신 원자 타입을 쓴다

`volatile` 은 **가시성만** 보장하고 원자성은 보장하지 않는다. `flag = !flag`·`count++` 처럼
읽고-쓰는 조합에서는 아무것도 지켜주지 않는데, 읽는 사람은 "이 필드는 스레드 안전하다"고
오해하기 쉽다.

| 용도 | 대체 |
|---|---|
| 종료·상태 플래그 | `AtomicBoolean` |
| 카운터 | `AtomicInteger` / `AtomicLong` |
| 참조 교체 | `AtomicReference` |
| 여러 필드를 함께 읽고 쓰는 복합 조건 | `synchronized` 또는 `ReentrantLock` |

**가시성 요구 자체를 없애면 안 된다.** `volatile` 을 그냥 지우는 것은 수정이 아니라 **버그 주입**이다 —
스레드 A가 세운 플래그를 B가 영원히 못 볼 수 있고, 이 결함은 컴파일·테스트를 모두 통과한 뒤
운영에서만, 그것도 비결정적으로 드러난다. 반드시 동등하거나 더 강한 수단으로 교체한다.

## 13. 새 API 에 가변 인자를 두지 않는다

`Type... args` 는 호출부에서 **인자 개수·타입 오류를 컴파일러가 잡지 못하게** 하고,
배열 생성을 숨기며, 오버로딩 해석을 모호하게 만든다.

```java
public static byte[] merge(Path... paths)       // ❌
public static byte[] merge(List<Path> paths)    // ✅ 0개·1개도 타입으로 드러난다
```

"1개 이상"이어야 하면 `first, List<T> rest` 로 표현한다. varargs 는 0개를 막지 못해
런타임 검사에 의존하게 된다.

**대상이 아닌 것** — 프레임워크·인터페이스 오버라이드(시그니처를 우리가 정하지 않는다),
외부 제공 라이브러리의 공개 API, `String.format`·`log.info` 같은 표준 호출의 *사용*.
이 절이 막는 것은 **우리가 varargs 를 선언하는 것**이다.
