# Entity 규칙 — Java · Spring

> [_프로젝트에서_정할_것.md](../_프로젝트에서_정할_것.md)

## 1. 상태 변경은 의도가 드러나는 메서드로만

`@Setter` 를 쓰지 않는다. 하나의 `update()` 에 모든 필드를 몰아넣지도 않는다.

```java
public void rename(String name) { Assert.hasText(name, "이름은 필수입니다."); this.name = name; }
public void deactivate() { this.active = false; }
```

호출부만 읽고도 도메인 규칙이 보이고, 상태 전이 조건을 한곳에서 검증할 수 있다.

## 2. 생성은 정적 팩토리 또는 빌더 생성자로

- 정적 팩토리(`of()`·`from()`) 를 우선한다. 복잡하면 **생성자 레벨**에 `@Builder` 를 붙이고
  필수값을 검증한다.
- **클래스 레벨 `@Builder` + `@AllArgsConstructor` 는 금지한다.** 모든 필드가 열린다.
- `@Builder.Default` 를 쓰지 않는다. 기본값은 필드 초기화나 생성자 안에서 명시한다.
- `@NoArgsConstructor(access = PROTECTED)` 로 외부 직접 생성을 막는다.

## 3. 연관관계는 ID 참조로

- `@ManyToOne`·`@OneToMany` 를 쓰지 않는다. FK 는 ID 필드로 직접 보유한다.
- 연관 데이터는 조인으로 한 번에 조회하거나 필요한 시점에 각각 조회한다.
- 결합도가 낮아지고 N+1 이 생기지 않으며 실행되는 쿼리가 명확해진다.

## 4. 감사 필드는 공통 상위 타입에 모은다

등록·변경의 일시와 주체를 공통 상위 타입에 두고 모든 엔티티가 상속한다.
값은 **비즈니스 로직이 직접 설정하지 않고** 영속 계층의 인터셉터가 채운다.

- **사용자 ID 는 처리 주체를 식별한다** — API 는 로그인 사용자, 워커·배치는 각자의 식별자.
  사후 추적의 유일한 영속 근거이므로, **컬럼 폭을 넘으면 잘라내지 말고 기동을 실패시킨다.**
  잘린 식별자는 값이 비는 것보다 나쁘다.
- **실행 주체와 마킹 주체가 다르면 합성한다.** 한쪽이 실행하고 다른 쪽이 상태를 마킹하는
  행은 감사값이 "마지막에 쓴 주체"만 남아 **틀린 주체를 가리킨다.** 두 식별자를 이어 붙인다.
- **일시는 앱 시계가 소유한다** → [time-and-clock.md](time-and-clock.md)

## 5. Javadoc

전역 규칙([coding-standards.md](coding-standards.md))에 더해 엔티티는 아래를 지킨다.

- 클래스: 역할 한 문장 + 관련 엔티티 `@see`
- 필드: 의미·제약 한 줄. ID 필드는 생성 전략·불변성, FK 는 참조 대상을 명시
- 빌더·비즈니스 메서드: 의도 + `@param`/`@throws`
