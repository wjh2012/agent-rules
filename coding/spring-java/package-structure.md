## 도메인 내부 계층

모든 도메인은 아래 하위 패키지를 가진다(필요한 것만 만든다).

| 패키지 | 필수 | 역할 |
|---|---|---|
| `api` | O | Controller |
| `service` | O | 비즈니스 로직 |
| `repository` | O | 영속 계층 인터페이스 |
| `entity` | O | 엔티티 |
| `dto` | O | 요청·응답 DTO |
| `exception` | - | 도메인 전용 예외·오류 코드 |
| `util` | - | 도메인 전용 유틸리티 |

## 의존성 방향은 단방향이다

```
api → service → repository → entity
         ↓
        dto
```

- 역방향 의존을 만들지 않는다.
- 공통(`global`·`support`) 패키지는 모든 도메인이 참조할 수 있지만,
  **공통이 특정 도메인을 참조하면 안 된다.**
- 도메인 사이는 같은 계층의 `service` 를 주입해 쓴다. 남의 `repository` 를 직접 참조하지 않는다.
- 모듈 사이는 빌드 의존 방향을 따른다. 역방향 금지.

## 모듈 경계가 애너테이션 부착 가능 여부를 가른다

의존을 어느 모듈에 두느냐에 따라, **같은 "DTO" 라도 어디 사는지에 따라 붙일 수 있는 애너테이션이
달라진다.**

- 웹·문서화·검증 의존(OpenAPI·Bean Validation)은 API 모듈에만 둔다.
- 공유 모듈의 DTO 에는 그 애너테이션을 붙이지 않는다. 붙이려면 공유 모듈이 웹 의존을 갖게 되어
  모듈 경계가 무너진다.
- 라이브러리 성격의 모듈은 앱 프레임워크에 의존하지 않는다.

## 새 도메인을 만들 때

1. 어느 모듈에 속하는지 먼저 정한다
2. 필수 패키지를 만든다
3. 도메인 전용 예외·오류 코드가 필요하면 `exception` 을 추가한다
