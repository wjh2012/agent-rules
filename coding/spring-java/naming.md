## 1. 컨트롤러 메서드명은 전역 고유

도메인 접두어를 붙이고 약어를 쓰지 않는다. 조회는 `get` + 대상 명사의 단수·복수.
근거와 상세는 [api.md §2](api.md).

## 2. 「행위 + 직접목적어」로 의도를 드러낸다

메서드명은 무엇을 하는지가 아니라 **무엇에 무엇을 하는지**가 보여야 한다.
수신자 이름을 메서드명에 반복하지 않는다 — `reqImg.linkReqImgToHubImg(...)` 가 아니라
`reqImg.linkToHubImg(...)` 다.

짧게 줄여서 방향이 모호해지면, **방향은 첫 인자와 Javadoc 으로 못박는다.**
이름을 길게 늘려 무모호하게 만드는 것보다 낫다.

## 3. 경로 식별자는 절대·상대를 이름에 드러낸다

경로를 담는 변수·필드·파라미터는 그것이 절대경로인지 특정 기준 아래의 상대경로인지
**이름에서 구분되게** 한다. 구분이 안 되면 결합 지점에서 조용히 틀린 경로가 만들어진다.
이름으로 다 드러내기 어려우면 Javadoc 에 기준점을 적는다.

## 4. 인스턴스 변수·파라미터는 타입을 head 로

변수명의 마지막 단어가 타입을 가리키게 한다(`targetUser`, `sourceUser`).
역할어(`target`·`source`)는 **같은 타입이 둘 이상 있어 구분이 필요할 때만** 붙인다.
하나뿐이면 타입 이름 그대로가 가장 읽기 쉽다.

## 5. 외부 설정 키

앱 고유 설정은 **단일 루트 아래**로 모은다. 프레임워크·라이브러리 키와 섞지 않는다.
루트 이름은 프로젝트에서 정하고 그 아래를 도메인별로 나눈다.

## 6. Boolean

여부를 뜻하는 필드는 이름만으로 참일 때의 의미가 드러나게 한다.
부정형 이름(`notDeleted`·`disabled`)을 만들지 않는다 — 조건문에서 부정의 부정이 된다.
