# 예외 처리 — Java · Spring

> 응답 포맷·예외 계층의 구체 형태는 프로젝트마다 다르다 →
> [_프로젝트에서_정할_것.md](../_프로젝트에서_정할_것.md)

## 원칙

1. **비즈니스 예외는 전부 unchecked** (RuntimeException 계열). checked 예외를 만들지 않는다.
   파일 I/O 실패는 `UncheckedIOException` 으로 전파한다.
2. **Controller 에서 예외를 catch 하지 않는다.** 전역 핸들러로 전파한다.
3. **예외를 HTTP 응답으로 바꾸는 곳은 전역 핸들러 한 곳뿐이다.**
4. **4xx 와 5xx 를 구분한다.** 입력·요청 문제는 4xx 로 `warn`(스택트레이스 없이),
   서버·엔진 문제는 5xx 로 `error`(스택트레이스 포함).
5. **라이브러리 모듈은 앱의 예외 프레임워크에 의존하지 않는다.** JDK 표준 예외나 자체 예외만
   던진다. 공통 예외 타입은 여러 앱이 공유하는 모듈에 둔다.

## 도메인 예외를 타입으로 나눌 것인가

**기본은 나누지 않는 쪽이다.** 공통 베이스 예외 하나에 코드 enum 을 실어 던지고,
도메인 구분은 그 enum 값이 담당한다.

```java
throw new BusinessException(UserErrorCode.USER_NOT_FOUND);
```

근거는 Effective Java Item 72 다. 커스텀 예외 **타입**은 둘 중 하나일 때만 값을 한다 —
(1) 그 타입으로 `catch` 되어 분기에 쓰이거나, (2) 표준 예외에 없는 상태를 담거나.
공통 베이스 예외는 둘 다 만족한다(코드 상태를 보유하고, 전역 핸들러가 이 타입을 집어 잡는다).
반면 도메인별 서브클래스는 자기 타입으로 잡히지도(핸들러는 enum 으로 분기한다) 상태를 더하지도
않는다. 유일한 이득인 "생성자 타입 제약"은 클래스 수가 두 배가 되는 값어치가 없다.

정말로 타입 `catch` 가 필요한 분기가 생기면 **그때 그 예외만** 도입한다.

## 스택트레이스를 잃지 않는다

| 금지 | 대신 |
|---|---|
| `e.printStackTrace()` | `log.error(msg, e)` |
| `throw new X(e.getMessage())` | `throw new X(..., e)` — cause 를 넘긴다 |
| `log.warn("실패: {}", e.getMessage())` | `log.warn("실패 id={}", id, e)` — **예외 객체를 마지막 인자로** |

4xx 처럼 스택이 무의미한 경로는 생략할 수 있다. 단 **생략 근거를 주석에 남긴다.**
근거 없이 예외 객체만 빠뜨린 것은 위반이다.

## 빈 catch 를 만들지 않는다

본문이 빈 `catch` 는 무조건 위반이다. 이유 주석만 달고 로그를 빠뜨린 것도 위반이다 —
주석은 런타임에 아무것도 남기지 않으므로, 그 catch 가 삼킨 예외는 영원히 관측되지 않는다.

무시가 정당하면(best-effort 정리 등) **세 가지를 모두** 갖춘다.

```java
try {
    Files.deleteIfExists(p);
} catch (IOException ignored) {                    // 1. 변수명 ignored
    // 임시파일 정리는 best-effort — 삭제 실패가 결과에 영향을 주지 않는다.   2. 무시해도 되는 이유
    log.debug("임시파일 삭제 실패 path={}", p, ignored);                  // 3. 흔적
}
```

로그 레벨은 무시의 성격을 따른다 — 정상 경로의 best-effort 는 `debug`,
드물게 일어나야 하는 무시는 `warn`.

**테스트 코드도 같다.** 로거가 없으면 예외를 삼키지 말고 `throws` 로 내보내거나,
예외 발생 자체가 검증 대상이면 그것을 단언한다.

## 원인 체인을 문자열 슬롯에 담을 때

DB 오류 컬럼·이벤트 메시지처럼 **단일 문자열 슬롯**에 원인을 적재할 때 `e.toString()` 을
쓰지 않는다. 최상위 예외만 나오고 래핑된 근본 원인이 사라진다.
원인 체인을 `Type: msg ← Type: msg …` 한 줄로 펼쳐 담는 유틸을 두고 그것을 쓴다.

스택트레이스는 이와 별개로 항상 로거에 남긴다.
